# Springer Phase 0: repository foundation

## Context

[The build plan](../todo/2026-09-08-build-springer-a-diatonic-chord-generator-midi-fx.md) scopes Phase 0 as "Repo foundation: AGENTS.md and CLAUDE.md symlink, `.claude/`, `.github/` workflows and `*.instructions.md`, lint configs, `docs/{adr,design,plans}`, the v4 script preserved verbatim as `docs/design/diatonic-chord-trigger-v4.js`, the thirteen ADRs", gated on "CI green on the scaffolding: markdownlint, typos, gitleaks, shellcheck".

The repository currently holds four tracked files: a three-line `.gitignore`, an MIT `LICENSE`, a three-paragraph `README.md`, and the build plan. `docs/design/diatonic-chord-trigger-v4.js` arrived during planning and is the fifth. There is no `.github/`, no `.claude/`, no `AGENTS.md`, no `docs/adr/`, and no build layer of any kind.

Phase 0 exists to make every later phase's decisions citable rather than remembered, and to make the first real code arrive into a repository that already knows how to check it. Nothing in Phase 0 is Zig. The build skeleton is Phase 1, deliberately, because `build.zig.zon` is what CI reads for the toolchain version and shipping a workflow that references a file which does not exist yet would mean Phase 0 ends with red CI.

The sibling project [`fosforo`](https://github.com/cboone/fosforo) (`~/Development/fosforo`) is the structural precedent, and most of Phase 0 is adaptation rather than invention.

## Findings that shaped the plan

### `bootstrap-project` cannot be used as the entry point

Claude Code loads the plugin **cache** copy, `bootstrap-project` v1.3.1, not the marketplace checkout. That copy's step 5 instructs the agent to read files such as `plugins/set-up-ci/commands/set-up-ci.md`, and no `commands/` directory exists anywhere in `agent-harness-plugins`. It also names the tools `setup-ci`, `setup-linters`, `setup-secret-scanning`, which are not the installed skill names (`set-up-*`). The marketplace checkout has fixed both, but that fix is not in the cache.

The individual skills are unaffected. Phase 0 therefore invokes `scaffold-new-repo`, `set-up-secret-scanning`, and `set-up-linters` directly, in `bootstrap-project`'s own documented order, and skips the orchestrator. This is worth filing upstream against `cboone/agent-harness-plugins`.

### There is no Zig scaffolder, and `set-up-ci` cannot run yet

`scaffold-new-repo` accepts `zig-cli` as a project type, but that selects only a `.gitignore` template and a README installation snippet. It generates no `build.zig`, no `build.zig.zon`, no `src/`. There is no Zig analogue to `scaffold-go-cli`.

`set-up-ci` does have a Zig template, and it is a one-line call to `cboone/gh-actions/.github/workflows/run-zig-ci.yml` with `zig-version-file: build.zig.zon`. The skill's own notes say that file is "always present in a Zig project; no action needed", an assumption Phase 0 breaks. `set-up-ci` therefore runs in Phase 1, alongside the build skeleton it describes.

### The reusable workflows cover three of the four gate tools

`cboone/gh-actions` (currently `91f9abd25d4f82354c0f950dfc8b6d7525b0f5b5`, v3.0.0) exposes `lint-text.yml`, `lint-shell.yml`, `lint-github-actions.yml`, and `scan-for-secrets.yml`. Between them they cover markdownlint, Prettier, cspell, yamllint, ShellCheck, shfmt, actionlint, gitleaks, and TruffleHog.

`lint-text.yml` has no typos input. Its inputs are `node-version`, `run-markdownlint`, `run-prettier`, `run-cspell`, `run-yamllint`, `preset`, `use-consumer-versions`, and `timeout-minutes`. So typos needs its own job, adapted from fosforo's `typos.yml`, which pins both the version and the release tarball's SHA256 and emits a `--format brief` step summary on failure.

Separately, `set-up-linters` offers typos only on its Rust path; it recommends cspell everywhere else. The `typos.toml` is adapted from fosforo rather than generated.

### Prettier will try to reformat the preserved v4 script

`lint-text.yml` runs Prettier by default, and Prettier formats `.js`. `docs/design/diatonic-chord-trigger-v4.js` is preserved verbatim as the normative statement of the plugin's behavior, and the reference vectors in Phase 2 are generated by running it. Reformatting it would edit a historical record and invalidate the thing the vectors are measured against.

`.prettierignore` must exclude `docs/design/` before the first CI run. This is the single highest-consequence detail in Phase 0.

For the same reason Prettier is scoped away from Markdown entirely: markdownlint owns Markdown, and Prettier's table reflowing and emphasis normalization would otherwise contend with `MD060` and `MD049`/`MD050`. Prettier keeps JSON and YAML.

### The shell gate is vacuous in Phase 0, and has a Phase 1 gap

`lint-shell.yml` finds scripts two ways: `find . \( -name '*.sh' -o -name '*.bash' \)`, and `find bin/ scripts/ script/ -type f | file --mime-type | grep text/x-shellscript`. Phase 0 adds no shell scripts at all, so the job passes by finding nothing. That is a check which cannot fail, and it should be stated rather than counted as coverage.

The Phase 1 consequence is sharper. fosforo keeps two extensionless shell scripts under `cmake/` (`narrow-au-resource-usage`, `set-au-display-name`), and Springer's build architecture adapts them. `lint-shell.yml` looks only in `bin/`, `scripts/`, and `script/`, so those two would be silently unlinted, which reads exactly like passing. fosforo's own pipeline avoids this by discovering through shebang instead of location:

```bash
git ls-files -z | xargs -0 shfmt -f | xargs -r shfmt -d
git ls-files -z | xargs -0 shfmt -f | xargs -r shellcheck
```

Phase 0 calls `lint-shell.yml` because it is correct for `scripts/`. Phase 1 must either switch to the pipeline above or add a path input upstream, and this is recorded as an AGENTS.md gotcha so it is not rediscovered.

### `clap.octave-number/1` exists, and no host implements it

Measured 2026-09-08 against CLAP 1.2.10. `clap/ext/draft/octave-number.h` defines `clap.octave-number/1`, by which a host pushes `set_note60_octave(plugin, int8_t)` on the main thread to tell a plugin whether note 60 is C3, C4, or C5. The header names the exact problem v4's `Middle C Is` parameter solves by hand.

It is unusable today, for four independent reasons:

- A GitHub code search for `set_note60_octave` returns 12 results, every one a vendored copy of the header or a mechanical language binding. No host calls it; no plugin implements it.
- clap-wrapper has zero references to `octave_number` or `CLAP_EXT_OCTAVE_NUMBER`, so even an implementing host could not reach Springer through the AUv2 path, which is the path Logic uses.
- AUv2 has no equivalent property. The only mentions of middle C in the macOS SDK are prose comments in `MusicDevice.h` and `AudioUnitParameters.h` noting that note 60 is middle C.
- It is push-only and draft. There is no `clap_host_octave_number` to query, and it is absent from `clap/clap.h`, living only in `clap/all.h`.

The mapping, for whenever this becomes real: `middle_c_param = note60_octave - 3`, since v4 computes `Math.floor(pitch / 12) - 2 + param` and defaults the parameter to `1` (C4, Roland).

### v4 carries two parameters the build plan's table omits

`Trace Chord Names` (index 21) and `Middle C Is` (index 22). The build plan's parameter table totals 44 and accounts for neither.

Both are deferred, and the deferral is recorded rather than silent. `Trace Chord Names` is superseded by `src/clap/log.zig` talking to the host's `clap.log`. `Middle C Is` changes only the octave number appended to a note name, and no name is displayed until the GUI exists, so it rides along with ADR 0013. `src/music/spelling.zig` takes `note60_octave: i8` as a function argument defaulting to 3, staying pure and naming no CLAP type.

Deferring costs nothing here, and that is the point. ADR 0008 makes parameters stable by `clap_id`, so one can be added later without disturbing any existing automation. Scripter's binding to array index is precisely what made v4's parameter order frozen and forced every addition to the end; Springer is not subject to that, and Phase 0 should not act as though it were.

### The reference-vector stub list is incomplete

The build plan names `NoteOn`, `NoteOff`, `ControlChange`, `GetParameter`, `SetParameter`, `GetTimingInfo`, `sendAfterMilliseconds`, and `Trace`. Reading the script adds two requirements:

- `Reset()` calls `MIDI.allNotesOff()`, so the harness needs a `MIDI` object.
- `GetParameter` is keyed by **name** throughout (`GetParameter("Chord Tones")`) while `SetParameter` is keyed by **index** (`SetParameter(PARAM_ACTIVE, ...)`). The stub needs both lookups over one table.

This belongs in Phase 2, but it is recorded in AGENTS.md now, while the reading is fresh.

### Existing documents already pass the gate

Measured in the worktree before any config was written: `typos` exits 0 with no findings across the whole repository, including the v4 script. Under fosforo's `.markdownlint-cli2.jsonc`, both `README.md` and the build plan report 0 errors. Under markdownlint's defaults they report 30-odd `MD013` line-length errors, which is the rule fosforo disables on the grounds that prose is one long line per paragraph and hard wrapping makes diffs noisy.

So adopting fosforo's config makes the gate green on the first run rather than starting with a cleanup.

### There is no ADR tooling anywhere

No skill, no template, no generator, in any installed marketplace. The thirteen ADRs are authored against fosforo's format by hand: `# NNNN. Title in sentence case`, `**Status:** Accepted`, then `## Context`, `## Decision`, `## Consequences`. Filenames are `NNNN-kebab-case.md`, zero-padded, never renumbered, with dots in versions becoming hyphens (`0002-zig-pinned-to-0-16-0.md`). Decisions are superseded by an appended `## Amends ADR NNNN` section, never edited.

### 0.3 Lint and format configuration

Invoke `set-up-linters` after 0.2, not before: it offers actionlint only when `.github/workflows/` already exists, and 0.2 is what creates it.

- **`.editorconfig`** takes fosforo's `[*.{zig,zon}]`, `[*.{c,cpp,h}]`, `[CMakeLists.txt]`, and `[*.md]` sections. The extensionless-script section is deferred to Phase 1, when `scripts/` gains its first file; the comment explaining why each script must be named individually is carried with it.
- **`.prettierignore`** must contain `docs/design/`, for the reason in Findings. It must also exclude Markdown, so markdownlint owns it uncontested.
- **`.prettierrc.json`** keeps `printWidth: 10000` and `proseWrap: preserve` even with Markdown excluded, since both are house defaults and neither harms JSON or YAML.

Write **`typos.toml`** by hand, adapted from fosforo. Two entries carry over with their reasoning intact: the `` `[0-9a-f]{7,40}` `` pattern, because every action is pinned by commit and short SHAs in prose otherwise read as misspellings; and the `spellchecker:off` / `spellchecker:on` span, which is the only way a document can quote a misspelling in order to explain it. Drop the three `extend-words` and `extend-identifiers` entries fosforo carries, which are specific to its own vocabulary. Add `extend-exclude` for `zig-out/`, `zig-pkg/`, and `build/`.

The escape hatch is not hypothetical, and this plan proved it before the config existed. An earlier draft of the paragraph above named fosforo's three suppressed words literally, in order to say they were being dropped, and `typos` flagged all three. A document that explains a suppression by quoting it fails the check it is explaining, which is exactly the case the marked span exists for. Until `typos.toml` lands in this step, the only remedy is to not name them; afterwards, wrap the span.

typos otherwise passes clean across the repository including the v4 script, so no exclusion for `docs/design/` is needed. Re-run after writing the ADRs, which introduce most of the project's new vocabulary.

### 0.4 The lint workflow

One file, `.github/workflows/text-lint.yml`, with four jobs. Three call reusable workflows; the fourth is inline because no reusable workflow covers typos.

```yaml
jobs:
  text:
    uses: cboone/gh-actions/.github/workflows/lint-text.yml@<sha> # v3.0.0
    with:
      run-markdownlint: true
      run-prettier: true
      run-cspell: false
      run-yamllint: true
  shell:
    uses: cboone/gh-actions/.github/workflows/lint-shell.yml@<sha> # v3.0.0
  actions:
    uses: cboone/gh-actions/.github/workflows/lint-github-actions.yml@<sha> # v3.0.0
  typos:
    # inline; adapted from fosforo's typos.yml
```

Refresh the pin at authoring time rather than copying the SHA above:

```bash
TAG="$(gh release view --repo cboone/gh-actions --json tagName --jq '.tagName')"
SHA="$(gh api "repos/cboone/gh-actions/commits/${TAG}" --jq '.sha')"
```

The typos job pins `TYPOS_VERSION` (1.50.1 is current, matching the local install) **and** the release tarball's SHA256, on fosforo's stated grounds that a release asset can be replaced in place under the same tag. It runs on `ubuntu-latest`, and it emits a `--format brief` step summary on failure.

**This workflow carries no `paths-ignore`.** That is deliberate and it is the one rule worth stating in a comment, in fosforo's words: a check must not be able to skip the change that governs it. `typos.toml`, `.markdownlint-cli2.jsonc`, and this file all live inside the set these jobs scan, and every Phase 0 change is a Markdown change. A `paths-ignore` listing `docs/**` and `*.md` (which Phase 1's `ci.yml` will correctly carry, being a set of macOS builds) would make this workflow green on precisely the pull requests that could fail it.

### 0.5 AGENTS.md

fosforo's is 418 lines built over 472 commits, most of it a `## Gotchas` section. Springer's cannot be that yet and should not pretend to be. Seed the structure, then let it grow.

Sections: `## Overview`, `## Current state`, `## Non-negotiables` (one bold-lead bullet per ADR, prefaced with fosforo's "do not relitigate them in code review; supersede them with a new ADR instead"), `## Structure` (the build plan's source tree, marked as planned rather than present), `## Development` (what actually runs today, which in Phase 0 is the four lint tools), and `## Gotchas`.

Seed `## Gotchas` with what is already known and measured, rather than leaving it empty:

- **`@divFloor` and `@mod`, never `/` and `%`, in the degree arithmetic.** JavaScript's `Math.floor` floors toward negative infinity; Zig's `/` and `%` on signed integers truncate toward zero. Every pitch below the reference root lands on the wrong degree otherwise. A later refactor to `/` would compile and pass any test that only plays above the root, which is why the build plan calls for a source canary and not only a unit test.
- **`degreeOfPitch` can return `best = N`.** The v4 guard at line 148 handles a pitch class nearer the next octave's root than this octave's last degree by returning a degree one full step past the last index. It is not an off-by-one.
- **`features[0]` is load-bearing.** clap-wrapper's `build-helper.cpp` maps it to the AU type, and only `CLAP_PLUGIN_FEATURE_NOTE_EFFECT` yields `aumi`. Anything unrecognized falls back to `aumu` with a warning.
- **clap-wrapper must be pinned newer than fosforo's.** fosforo's `35f524b7` (2026-07-13) predates PRs #493, #497, and #498, which together make a note effect viable as an AUv2. Pin `1cca996e96f29ab2be7ae9f8cfe532bbc92e1dd6` (2026-08-08) or later.
- **`lint-shell.yml` does not look in `cmake/`.** Per Findings; Phase 1's problem, recorded now.
- **Prettier formats `.js`, and the v4 script is a historical record.** Per Findings.
- **The Scripter stub table needs two lookups.** `GetParameter` by name, `SetParameter` by index, plus a `MIDI.allNotesOff`. Per Findings.
- **`clap.octave-number/1` is specified but unimplemented.** Per Findings, with the measurement date.
